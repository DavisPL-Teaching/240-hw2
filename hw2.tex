\item
In class (Lecture 2, Part 1)
we discussed that for compilers, there are three different languages involved -- each with their own semantics, and a valid compiler must be consistent with all three of them. Namely:
\begin{itemize}
\item The source language $S$ (language in which we write the program)
\item The meta language $M$ (language in which we write the compiler)
\item The target language $T$ (language to which we compile the program).
\end{itemize}

This problem asks you to complete the definition of a \emph{correct} compiler (one which implements the semantics), based on these three semantics.

\begin{enumerate}[(a)]

A compiler $C$ is a program in the metalanguage $M$.

\end{definition}

\item
Use your definition to prove the following:
If $C_1$ is a correct compiler from $S$ to $T$, and $C_2$ is a correct compiler from $T$ to $U$, then the compiler $C$ defined by the following pseudocode is a correct compiler from $S$ to $U$:
\begin{verbatim}
    Compiler C from S to U:
    On input prog:
    - Run C1: set out1 = C1(prog).
    - Run C2 on the result: set out2 = C2(output1).
    - Return out2.
\end{verbatim}

You may assume that the meta-language $M$ runs the pseudocode above in the way that you would expect (i.e., it runs $C_1$, followed by $C_2$, and returns the result, similar to how \texttt{Seq} works for \texttt{RandProg}.)

\textbf{Note:} This part is essentially showing that compiling a program through an intermediate representation works out. In this case,
the intermediate representation is $T$ and the overall compiler is from $S$ to $U$.

\item
Use your definition to prove the following:
If $C$ is a correct compiler from $S$ to $T$, and $I_T$ is an interpreter for $T$ that implements the semantics, then
running $C$, followed by running $I_T$ on the result, results in a correct interpreter for $S$. That is:
\begin{verbatim}
    Interpreter I_S for S:
    On input (INPUT, prog):
    - Run C: set out = C(prog).
    - Run I_T((INPUT, out)).
\end{verbatim}

You may assume that the meta-language $M$ runs the pseudocode above in the way that you would expect (i.e., it runs $C$ followed by $I_T$).

\item
Define the ``do nothing'' compiler from $S$ to $S$
to be a compiler which simply takes the input program, and returns it without any changes. This is a program in the metalanguage $M$ such that
$$
(\texttt{INPUT}, \texttt{do\_nothing}, \texttt{OUTPUT})
$$
is valid if and only if $\texttt{INPUT} = \texttt{OUTPUT}$.

Use your definition to prove or disprove the following:
Regardless of the semantics of $S$, and even if $S$ is nondeterministic,
a do-nothing compiler is a valid compiler from $S$ to itself.
\end{enumerate}
